Food Animal Personality Quiz

Side Project

「食べ方で、その人の性格がわかるのでは？」

同僚の誕生日ランチでの雑談がきっかけでした。食の好みが人によってかなり違うことに気づき、 「食の性格診断」を作ってみようと思い立ちました。 同時に、Generative AI を使えば企画からイラスト、フロントエンド開発まで 一人で完結できるのか試してみたかったのもあります。

制作で取り組んだのは主に3つです：
• ロジック設計：MBTI を参考に「食の四象限」スコアリングモデルを構築し、ランダムではない根拠ある結果を出せるようにしました。
• ビジュアルの統一：Midjourney の Prompt を繰り返しテストし、16枚のキャラクターイラストを同じスタイルに揃えました。
• フロントエンド実装：JSON ベースのウェイトシステムで設問とスコアリングを管理し、HTML/JS でレスポンシブなインタラクティブページを構築しました。

インタラクション設計の判断

このプロジェクトの核心的な問い：「食の性格診断」の結果を、 当たっていると感じてもらい、シェアしたくなるようにするにはどうすればいいか？ 以下の3つが主な設計判断です。

3つの設計判断

1. 性格を動物で表現する

診断結果を具体的な動物キャラクター（例：格局象、慢熟貓）に対応させました。 抽象的な形容詞より動物のほうが覚えやすく、会話のきっかけにもなりやすいです。

2. キャラクターごとの「心の声」

結果ページの冒頭に、キャラクターの代表的なセリフを配置しました （例：儀式天鵝——「デザートの順番については、Excel で説明できます」）。 「まさに自分だ」と直感的に感じてもらい、スクリーンショットでのシェアにもつなげる狙いです。

3. ご飯友達 / ご飯災難マッチング

各結果に「一番合うご飯友達」と「一番合わない相手」を表示し、 「自分の結果を見る」から「友達をタグ付けする」へと体験を広げ、ソーシャルな要素を加えました。

ロジック設計

「味の好み」を「性格」に変換する

診断が「ランダムな当てずっぽう」にならないよう、 MBTI を参考にしたフレームワークを導入し、 あいまいな食の好みを定量化できる「四象限モデル」に落とし込みました。

食の性格 四つの軸

味覚 vs. 概念

物理的なおいしさで食べるか、 ストーリーや雰囲気で食べるか？

社交 vs. 一人

食事は人とつながるためか、 自分を回復させるためか？

保守 vs. 冒険

「パクチーピータンピザ」を前にして、イタリアの尊厳を守るか、 ワクワクして試してみるか？

計画 vs. 直感

注文時に栄養バランスを計算するか、 その時の気分で決めるか？

設問の設計例

Scenario: A popular dessert shop has two new items — which do you pick?

A. Chocolate donut — tried it many times, definitely delicious! 🍩
→ Deep-rooted [0, 0, +1, 0]

B. Chili cheese puff — never tried this flavor! Let me taste it 🌶️
→ Experimental [0, 0, -1, 0]

コンテンツ設計

ロジックラベルからキャラクター文へ

16組の性格コードはそのままでは無味乾燥な分類ラベルに過ぎず、 個性のあるキャラクター説明文に変換する必要がありました。 Prompt Chaining で LLM に「美食評論家」の口調で初稿を生成させ、 その後一つずつトーンを調整し、不自然な部分を削除して、全キャラクターの文体を統一しました。

ビジュアルシステム

16枚を同じセットに見せる

Midjourney で一番よく起きる問題は、生成するたびにスタイルが微妙にばらつくことです。 16枚の結果カードを同じ図鑑のように見せるために、Prompt のパラメータを繰り返し調整し、 最終的に「すみっコぐらし風」をスタイルの基準点として収束させました。

Prompt の主要パラメータ

スタイル基準：pastel sketchy style, minimalist graphics, bold outlines.

雰囲気：クリーンな暖色クリーム背景、ソフトな照明。

フロントエンド実装

フロントエンド開発と AI 協業

アーキテクチャとロジックは自分で定義し、AI（Copilot/LLM）で実装コードの作成を補助しました。

データ構造設計

ウェイトベースのスコアリングシステムを設計し、 各設問の選択肢が四つの軸のスコアに動的に影響する仕組みにしました。

インタラクションロジック

動的ウェイト計算

配列スコアをリアルタイムに計算し、最終的に対応する性格キー （例：TSDM = 格局象）にマッピングします。

ソーシャルマッチングロジック

相性の良い（ご飯友達）と相性の悪い（ご飯災難）の 組み合わせを判定するロジック。例えば、論理重視の「儀式天鵝」と 直感型の「熱情狗」は相互に排他的になっています。

全体フロー

第1段階：ロジック設計

（人間）課題と目標を定義し、MBTI を参考にした「食の四象限」モデルを構築。

（成果物）16性格のロジック骨格。

第2段階：並行制作

トラック A コンテンツ：Prompt Chain 設計→AI が16性格の初稿を生成→人間が調整→確定テキスト＆JSON。

トラック B ビジュアル：スタイル基準を設定→Prompt テスト→Midjourney 生成→微調整→16枚のキャラクターカード。

第3段階：フロントエンド統合

（人間）スコアリングウェイトシステムとマッチングロジックを設計。

（AI Copilot）JavaScript ロジックと CSS の実装を補助。

（成果物）レスポンシブ対応のインタラクティブ Web ページ。

振り返り

やってみての所感

このプロジェクトを通じて、AI と協業する際にデザイナーの仕事の重心がどこに移るのか、 より具体的に実感できました。

アウトプットは速くなるが、判断はより重要になる

AI は大量のコピーや画像を素早く生成できますが、「どれが使えてどれがダメか」の判断は やはり人間の仕事です。選別と修正にかなりの時間を使いました。

開発サイクルは確かに短くなった

企画から公開まで数日程度で完了しました。 浮いた時間はインタラクションの調整や体験のテストに充てることができました。

全体として、ロジック・コピー・ビジュアル・フロントエンドまで一人で通した、 わりと一通りの AI 協業実践になりました。 どの工程で AI が役に立ち、どこは自分でやるしかないのかも、より明確になりました。
