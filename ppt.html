ATEN 產品推薦 AI Agent

從模糊需求到精準方案，加速專案成型的 AI業務分身

現有 B2B 銷售漏斗與痛點分析

1. 專案成型前 (Pre-project)

包含「解決方案提案」到「產品清單」。客戶通常帶著模糊的情境與痛點來詢問，需要花費大量時間溝通、釐清規格，最終產出產品型號清分單。

2. 售前階段 (Pre-sales)

現有痛點：業務需跨越多個獨立系統比對型號、料號與價格，耗費大量行政時間。(註：此階段之自動化 ANZ 團隊已著手處理)

3. 售後階段 (Post-sales)

目前已有 FAE AI 正在準備開放至官方網站，專注於提供客戶售後的智能技術支援與問題排除。

售前系統

  • 系統目標：
    在客戶或業務只有「環境需求」或「痛點」時，透過 AI 快速引導，讓使用者理解並找到最適合的解決方案或產品型號。
  • 無縫接軌銷售流程：
    我們的系統作為漏斗的最前端，負責將「模糊需求」收斂為「明確的產品清單」，並有機會在未來直接串接 ANZ 的售前系統，正式進入專案報價階段。
  • 預期效益：
    大幅縮短「需求探索」的週期，提升商機轉換率，同時降低業務的前期溝通成本。

Deliverables & Outcomes

使用者能得到什麼？ (User Value)

Before: 模糊的非結構化資訊

  • 口語痛點：「我有4台電腦和12個螢幕，需要互相切換有建議的產品?」
  • 競品連結：「這是一台 StarTech 的設備 (附上一長串網址)」
  • 模糊情境：「我要蓋一間會議室，常常會有1~2人或用筆電投影簡報，現場螢幕有兩個...」

After: 標準化報表與規格清單

  • 產出符合規格的產品比較與建議選擇優缺點。
  • 自動提煉規格並對標，生成「跨產品規格比較表」。
  • 自動解析語意，精準產出對應的「系統連線圖」和精確的「產品型號清單」。

情境一：從模糊需求找到對應產品

1. 意圖解析與規格收斂

系統能聽懂口語情境（如「1台PC、2個螢幕」），並自動轉換為實質的硬體參數（至少需 3 In 2 Out）。

2. 產品資料庫智能檢索

將收斂後的參數自動對接產品 API，篩選出完全符合條件的現行產品型號。

3. 動態推薦與優缺點分析

產出 2~3 款最合適產品並列出建議（例如：「型號 A 性價比高；型號 B 支援無縫切換但價格較高」），輔助快速決策。

情境二：從競品或硬規格找到精確產品

1. 規格轉譯收斂

將口語描述轉化為指定的 JSON 格式（如：{"type": "matrix", "video_in": "15-20"}）。

2. 競品網址解析

業務貼上競品網址，AI 自動讀取內容並轉換成標準化規格 JSON。

3. 精準資料檢索

將規格 JSON 作為 Query 參數，精確檢索 Builder 產品庫，找出完全符合的自家產品。

4. 動態生成建議

根據規格資料，用 UI 動態生成跨品牌比較表，輔助業務快速掌握差異。

情境三：從模糊需求到具體解決方案

漸進式需求收斂

透過對話引導，將「蓋會議室」轉化為精確的方案 Tag (如：[中型空間 10~17人], [需要 in-room PC])。

基於 Tag 方案過濾

自動串接 Builder 內已結構化的解決方案資料庫，在現有的 2000 多個方案中進行精準篩選。

智能視覺化輔助

產出型號清單後，透過產品 Port Render 將參數轉換為視覺化的連線圖，讓架構一目了然。

使用 AI 的技術與流程

AI Tech & Agentic Workflow

核心架構：「翻譯官」與「分析師」專業分工

翻譯官 (Translator Agent)

專注於資料的降噪與結構化

  • 負責將客戶模糊的口語、冗長的競品網址，精煉成後端看得懂的「產品篩選規格 JSON」與「需求總結」。
  • 配備「小翻譯員」與專屬工具箱 (如網頁爬取、專屬資訊集) 應對複雜場景。
  • 確保傳遞給資料庫的查詢條件 100% 精確。

分析師 (Analyst Agent)

專注於業務價值賦能與溝通

  • 處理心臟地帶（Data Retrieval）檢索出的 100% 真實資料，完全排除 AI 幻覺。
  • 將冰冷的檢索資料，結合翻譯官傳遞的需求總結，重新包裝成「客戶聽得懂的語言」。
  • 強制輸出結構化資料交由前端渲染 UI。

核心運作管線 (Workflow Pipeline)

1. 統一流程

無論是白話文情境還是競品分析，皆採用同一套標準化管線。

2. 意圖推論約束

透過往返溝通進行意圖推論，有效約束 AI 解決空間，確保方向不偏離。

3. 豐富武器庫

翻譯官具備「詢問框架模板」、「網頁爬取」等 Tools。

4. UI 結構化輸出

分析師最終輸出 UI JSON，產出高質感的比較表與解決方案清單。

未來開發藍圖與優化方向

Future Roadmap & Governance

產品體驗與工具擴展 (Milestones)

1. 需求詳細定義

深入分析用戶輸入習慣，優化對應的 UI 輸出（如客戶習慣的產品比較表格欄位）。

2. 完善專屬工具庫

盤整可用資源供 AI 調用 (API, Builder)，涵蓋更廣泛的資料檢索，提升精準度並降低 Token。

3. 前端視覺呈現

將 AI 產出的 JSON 轉換成高品質的比較表、系統連線圖與業務指導說明。

基於 Harness Engineering 的 AI 治理與防護

零幻覺與高穩定流程

產品檢索絕不依賴 LLM 內部記憶，強制透過 JSON 呼叫 Builder API 查詢，確保資料 100% 真實存在。同時建構防呆與自動重試機制 (Fallback)，即使在多輪對話中仍能產出一致、可靠的數據結果。

惡意流量攔截 (Guardrails)

導入多層前置防護機制，包含意圖分類器與關鍵字過濾，自動識別並攔截與業務無關的問題、Prompt Injection 攻擊及惡意指令注入，有效防止系統資源濫用與資料外洩風險。

Token 最佳化

透過精簡系統 Prompt、壓縮上下文歷史、移除冗餘欄位等策略，以最小 Token 量達成最精確輸出。搭配分層模型調度（簡單任務用輕量模型、複雜推理用旗艦模型），大幅降低長期營運成本。

附錄 (Appendix)

戰略定位：為什麼現在先不要做「售前報價 AI」？

生成式 AI 的強項

  • 處理高度的不確定性與模糊需求。
  • 強大的語意理解能力，能將口語轉化為系統參數。
  • 最適合應用於漏斗最前端的「需求探索」階段。

傳統自動化系統的強項

  • 絕對精準、零隨機性。
  • 售前資料包含機密價格，錯一個料號就無法出貨，不容許任何幻覺 (Hallucination) 風險。
  • 此極度要求確定性的任務，應由 ANZ 團隊建置嚴謹的後台系統來處理。

為什麼不直接讓 AI 爬取官網找產品？

實測痛點與底層限制

  • 非結構化困境： HTML 充滿無關雜訊，浪費 Token 且稀釋核心資訊。
  • 上下文迷失： 長文本容易讓 AI 漏看關鍵數值，導致填補常識產生致命幻覺。
  • 多模態落差： B2B 核心拓撲圖與 I/O 圖形資訊遺失，AI 無法理解全貌。
  • 行銷詞彙干擾： 難以穩定提煉「限制條件」或必定搭配的關聯性。

建議有效作法

  • API 規格篩選： 建立參數化網址機制，讓 AI直接傳遞參數抓取乾淨過濾結果。
    GET /api/products?type=matrix&video_in=15-20&video_out=8&resolution=4K
  • 多代理協作： 分層檢索，先判定大類別，再由特定 Agent 爬取子目錄。
  • 重整資料結構： 根本解法，從後端將規格與行銷分離，提供純淨 API (Builder 的 proAV 已完成)。

為何選擇 Agent + Function Calling？

比較維度 微調 (LoRA) 訓練專屬模型 單純 RAG (文件檢索) Agentic RAG + Function Calling (本作法)
前期開發成本 🔴 極高 (需備妥萬筆資料與算力) 🟡 中等 (需建置向量資料庫) 🟡 中等 (需設計 API 與定義 Prompt)
後續維護成本 🔴 極高 (規格變更需重訓) 🟡 中等 (需持續更新向量庫) 🟢 極低 (AI 端無須修改，無縫接軌)
運行 Token 成本 🟢 較低 (Prompt 較短) 🔴 偏高 (需塞入大量 Context) 🟡 中等 (僅依賴 JSON 結果)
資料準確度 🔴 低 (料號易生幻覺) 🟡 中等 (精確數值易錯) 🟢 極高 100% (直接調用真實 API 資料)

常見問題預備 (FAQ)

多語系支援

LLM 本身已具備多語言理解與生成能力，系統可直接支援英文、日文等語系客戶。產品資料庫的對應語系欄位，即可切換輸出語言。

準確率與 KPI 衡量

透過「規格命中率」與「使用者採納率」兩個維度量化追蹤。未來有機會串接 Salesforce 的 Pardot，讓用戶直接送出產品 List，以驗證規格命中率（從詢問次數轉換為 Leads）及使用者採納率（最終成案比例）。

推薦結果的品質提升

目前 AI 僅依據規格參數進行匹配，但前線 Sales 擁有場域經驗與搭配知識（如特定產業偏好、常見組合）。未來需將這些隱性知識結構化為 Skill，讓 AI 具備同等判斷力，從「規格符合」進化到「情境最適推薦」。以及在試配度分數也更加準確，例如:port 比需求更高規的會有更高的比重加權
