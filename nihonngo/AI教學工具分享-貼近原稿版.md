# 用 AI 打造你的專屬教學工具

> 從點子到實踐的心得分享  
> 對象：已經會使用 Claude、非工程背景的日文老師  
> 形式：熟人之間的一對一分享  
> 核心：AI 是能力放大器，老師原本的教學 Know-how 才是最重要的東西。

## 這一版的語氣

這不是一場很正式的技術課，也不是要教老師成為工程師。

老師本來就已經有在使用 Claude 做教材或小工具，所以我想分享的不是「AI 要怎麼用」，而是我自己在幫忙做這個網站之後，整理出來的一些判斷方式。

知道這些概念之後，老師不一定要親自做什麼技術操作，但是以後在跟 AI 討論時，會比較知道自己要問什麼、要注意什麼，也比較不容易一開始就把東西做得太複雜。

# 一、先說明：用 AI 開發工具或 App 是什麼？

## Vibe Coding

現在很常聽到一個詞叫 Vibe Coding。

簡單說，就是使用者不一定要自己寫程式，而是透過跟 AI 對話，告訴 AI 想做什麼，再一邊看結果、一邊調整，慢慢把工具做出來。

例如可以直接跟 AI 說：

> 我想要一個可以練習漢字、顯示筆順，而且可以列印成 A4 的網頁。

AI 先做一版，我們再跟它說哪裡不對：

- 這個字太小
- 筆順不好看
- 列印會跑版
- 我希望題目和答案可以切換

然後讓它繼續改。

所以老師不需要自己會寫每一行 Code。比較需要的是知道自己想解決什麼問題，並且看得出來 AI 做的東西是不是自己要的。

我覺得可以把 AI 想成一個能力很強、速度很快的實習生。它可以幫忙做很多事情，但還是需要有人告訴它方向，也需要有人檢查結果。

# 二、我會先把 AI 工具分成兩大類

這是我覺得新手一開始最需要知道的概念。

我大概會分成 A、B 兩類。兩者最大的差別，是工具完成後，學生使用時還需不需要 AI。

## A：用 AI 做一個服務或工具

也就是開發的時候有使用 AI，但是完成的工具本身沒有 AI 功能。

例如：

- 這次做的五十音／漢字字帖網站
- 單字卡
- 抽題工具
- 計時器
- 一般靜態教材網站

這一類最簡單。有時候只要做成靜態網站，就可以免費放到網路上。

AI 幫我們把程式寫完之後，學生每使用一次，不需要再去問一次 AI，所以不會一直消耗 Token。

## B：服務或工具本身有 AI 功能

例如：

- AI 模擬真人聊天的語言學習 App
- AI 作文批改
- AI 根據學生程度出題
- AI 個人化學習建議

這一類就不太一樣。學生每問一句話、每批改一篇作文、每生成一組題目，都可能需要再呼叫一次 AI。

如果要做成讓學生長期使用的獨立服務，通常也需要後端或代管服務，才能安全地處理帳號、API Key、使用紀錄和費用。

## 兩類的開發難度和商業成本差很多

一般傳統軟體開發完成後，每多一位使用者，增加的成本通常很低。

但是有 AI 功能的服務，每使用一次就可能消耗 Token、語音或其他 API 額度。如果一開始沒有算好，使用者愈多，反而燒錢燒得愈快。

所以在有點子之後，我覺得可以先問自己一句：

> 我是要用 AI 幫忙把工具做出來，還是這個工具在學生使用時也一定要有 AI？

這個答案會直接影響後面的難度和成本。

## Gemini Canvas 是一個比較特別的情況

Gemini Canvas 可以直接在 Gemini 的對話裡生成並預覽互動頁面，也可以快速加入 TTS 或 Gemini 功能。

所以新手不用先自己串 API，就有機會直接試玩一個有 AI 功能的 Prototype。像我們之前做的 N1 聽力工具和日語口語練習，就是很好的例子。

- [日本語聴解力テスト（N1 4択 & TTS）](https://gemini.google.com/share/504f148f337c?skid=60cd732b-e064-4c90-994d-317159cfadf6)
- [日語口語練習工具](https://gemini.google.com/share/9c367038fa42?skid=3cfa4950-cd35-4221-af28-71d35e40ebe5)

不過這比較像在 Gemini 裡面快速試做和分享，不代表已經是一個可以無限制給學生使用的正式產品。實際使用仍會受到平台、帳號、功能和額度限制，也要注意學生輸入的資料。

# 三、接著再理解：有沒有 Server 的差異

前面的 A、B 是在分「工具使用時需不需要 AI」。

接下來可以再問另一個問題：這個工具需不需要記住使用者？

## 用餐廳來比喻

- 前端：餐廳的裝潢和菜單，是使用者看得到、點得到的畫面
- 後端：餐廳的廚房，負責計算、驗證和處理規則
- 資料庫：冰箱和帳本，用來保存會員、教材和學習紀錄
- Server／雲端：餐廳使用的場地和設備，讓服務可以持續運作

## 哪些功能通常需要後端或類似 Server 的服務？

- 儲存學生資料
- 會員登入
- 保存學習進度
- 付費購買
- 留言或學生互動
- 安全地保存 AI API Key

Server 通常會有主機或服務成本，不過小規模服務有很多免費額度，費用有時比 AI Token 低很多。

真正增加難度的也不只是月租費。只要開始保存學生資料，就要考慮：

- 誰可以看到資料？
- 學生能不能看到別人的資料？
- 密碼和權限怎麼處理？
- 資料不見了怎麼辦？
- 有沒有個人資料或安全問題？

Google Sheet 搭配 Google Apps Script，可以算是一種比較容易入門、低成本的方案。它看起來不像自己架 Server，但其實是把後端工作交給 Google 的服務處理。

# 四、所以老師可以先想：自己要做哪一個等級的服務？

我先幫老師把常見的教學工具分成四個等級。

這裡的 Level 不是在說工具好不好，而是在說技術和營運責任有多大。

## Level 1：教學用或自用的小工具

不管是老師自己用，還是分享給學生用，只要不需要登入和儲存學生資料，通常都可以先做成靜態網站。

例如：

- 漢字寫字網站
- 單字抽題器
- 五十音練習
- 可以列印的講義生成器

這是最適合新手開始的等級。

如果使用 Gemini Canvas，也可能快速做出像 N1 聽力那樣帶有語音或 AI 功能的頁面；但這種分享方式仍會受到 Gemini 平台和帳號額度限制，不能直接假設可以無限提供給大量學生使用。

## Level 2：小規模給學生使用的工具

這時候開始像是學生服務，可以幫學生儲存資訊，或提供客製化內容。

例如：

- 記住學生背過哪些單字
- 保存學習進度
- 每個學生有自己的單字庫
- 老師可以更新學生的內容

這一類會需要 Server，或類似 Server 的東西。

「個人客製單字」就是一個例子：網頁負責顯示單字，Google Sheet 保存單字和熟悉度，Google Apps Script 負責讀取和更新。

- [個人客製單字（Google Sheet）](https://newslin-design.github.io/wordCard.html)

## Level 3：在學生服務中加入 AI

在 Level 2 的基礎上，再讓 AI 幫學生生成內容。

例如：

- 根據錯題生成新題目
- 根據學生程度調整文章
- AI 批改作文
- AI 提供個人化練習

這時候除了學生資料和後端，也開始產生 Token、語音和 AI 品質控制的問題。

## Level 4：對外商業化的教學服務

例如老師之前提過的 AI 模擬真人對話 App。

如果要公開收費，除了功能本身，還要處理：

- 大量使用者
- 會員和權限
- 付款
- 客服
- 資安和個人資料
- AI 回答品質
- Token 成本上限

這個等級通常就不只是把程式做出來而已，而是需要比較完整的產品和營運規劃。

# 五、這次做字帖網站，我自己整理出的幾個小技巧

## 1. 規格要明確，也要知道什麼先不要做

一開始很容易覺得，既然 AI 可以做，就想把所有功能一起放進去。

例如：

- 學生直接在上面作答
- 學生可以存檔
- 把結果回傳給老師
- 老師可以線上批改

這些不是完全做不到，而是做了之後就不再是簡單的靜態網站，會開始需要帳號、資料庫、權限和個人資料處理。

所以這次第一版先放棄學生存檔和回傳，只專心解決：

> 老師能不能快速得到一份好用、可以重複產生、可以互動、也可以列印的漢字練習紙？

我覺得刪掉功能不是失敗，而是先讓真正重要的功能完成。

## 2. 載體和架構也是規格的一部分

老師最開始是請 Claude 做 PDF。這很適合快速看到第一份成果。

但做完第一份後就會出現問題：

- 下一課是不是又要重新做一份？
- 版面要修改時，是不是每一頁都要改？
- 同一份漢字資料能不能重複使用？

所以後來我覺得，老師真正需要的不是一張 PDF，而是一個可以持續產生練習紙的工具。

> PDF 是最後的輸出，網頁是可以重複生產教材的工具。

網頁也可以列印或另存成 PDF，但是它比單一 PDF 更容易擴充，也可以加入筆順、模式切換和互動功能。

所以在跟 AI 定義規格時，不要只說「我要一個 PDF」，還可以先想：

> 我是只需要這一份完成品，還是以後會一直新增和修改內容？

## 3. 資料和 UI 要分開想

我會用「內餡和包裝」來說明。

### 內餡：資料

- 字庫從哪裡來？
- 漢字讀音和例詞是什麼？
- 筆順圖形從哪裡來？
- 題目和答案放在哪裡？

這次最難的其實不是畫面，而是筆順資料。

後來發現有開源的 KanjiVG，可以提供漢字筆順路徑，才解決最麻煩的資料問題。

### 包裝：UI 和功能

- 要不要列印按鈕？
- 描紅要多深？
- 筆順怎麼顯示？
- 練習和解答怎麼切換？
- A4 列印會不會跑版？

資料和 UI 分開後，之後增加新漢字時，只要加入資料，不需要重新設計整張頁面。模板修改一次，也可以套用到全部教材。

- [漢字練習網站](https://newslin-design.github.io/nihonngo/sheet.html?id=n3-02)
- [KanjiVG](https://kanjivg.tagaini.net/)

## 4. 知道 Claude Code 和一般 Chat 的差異

差別不只是「能不能寫 Code」。

一般 Chat 比較像一問一答。你貼一段內容，它根據你提供的內容回答，然後通常要由使用者把程式碼放回正確的位置。

Claude Code 或 Cursor 這類 Agent，可以直接理解整個專案資料夾：

- 自己尋找相關檔案
- 理解資料放在哪裡
- 同時修改多個檔案
- 執行檢查或測試
- 繼續根據結果修改

所以老師不需要自己會打終端機指令，也不需要自己修改每一行 Code。

比較重要的是：老師要能描述問題、確認方案，以及看實際結果是不是自己要的。

### 現場可以實際示範一次

第一步，先請 Claude Code 理解，不要急著改：

> 請先閱讀這個漢字練習網站的專案結構，暫時不要修改。告訴我教材資料、畫面模板和互動功能分別放在哪裡。

第二步，說明需求，請它先提方案：

> 我希望切換到解答模式時，答案更容易辨認。請先提出最小修改方案，不要立刻動手。

第三步，確認方向後再請它做：

> 這個方向可以。請完成修改，並檢查是否會影響練習模式和 A4 列印。

第四步，看結果後繼續用一般說話方式回饋：

> 螢幕上已經很清楚，但列印時顏色太淡。請只調整列印樣式，不要改變螢幕版本。

這個過程可以讓老師看到，使用者真正要做的是一直和 AI 對齊，而不是自己下去寫程式。

如果 Claude Code 在修改檔案或執行指令前詢問權限，看不懂時可以先不允許，請它用白話說明準備做什麼。

## 5. 幾個小規模、免費或低門檻的通用工具

### GitHub Pages

- 免費發布純前端靜態網站
- 適合 A 類、Level 1 的工具
- 網站完成後不需要持續支付 AI Token

### Google Apps Script

- 可以搭配 Google Sheet 使用
- 不必自己管理 Server
- 適合小規模、低流量的個人或教學工具

只要開始保存學生資料，仍然要注意權限和隱私，不能因為工具免費就忽略安全問題。

# 六、最後，我覺得老師可以先想自己的優勢

我一直覺得 AI 是能力放大器。

它可以把一個人原本就很厲害的部分放大，但也可能把原本的錯誤放大。

之前有很多人看到 Vibe Coding，就覺得自己突然什麼都能做，一開始就想做很大的產品。最後不一定有做出真正有人需要的東西，甚至可能花掉很多 Token 費用。

所以我覺得重點不是「有 AI 之後，我是不是什麼都能做」，而是：

> 我原本最了解、最有價值的東西是什麼？AI 可以怎麼幫我把它放大？

## 老師真正的優勢是教學 Know-how

### 1. 知道不同學生真正需要的內容

只有實際接觸學生的老師，才知道什麼國家、什麼目的、什麼程度的學生需要什麼單字庫。

例如台灣學生：

- 對很多漢字的字義其實很熟悉
- 但是日文讀音可能很弱
- 很多人學日文是為了旅遊、交朋友或理解日本文化
- 不一定每個人都是為了考試或工作

這會直接影響教材應該選哪些字、哪些例句和哪些情境。

### 2. 可以針對不同學生設計客製情境

老師真的接觸過學生，知道學生在哪些地方會卡住，也知道什麼例子能讓學生有反應。

一般工程師可能很會做功能，但不一定想得到：

- 初學者最常誤會什麼？
- 台灣學生看到哪個漢字會用中文方式猜？
- 旅遊日文和 JLPT 日文需要的練習有什麼不同？
- 哪種題目在課堂上好用，但回家自學時不好用？

### 3. 能判斷 AI 產生的內容到底能不能教

AI 可以大量生成單字、例句和題目，但生成得快不等於適合拿去教。

老師可以判斷：

- 難度是否符合學生程度
- 例句是否自然
- 內容是否符合實際文化和情境
- 錯誤答案是否真的有教學價值
- 學生會不會因為介面或說明而誤解

### 4. 有真實學生，可以形成快速回饋循環

老師可以把工具拿到真實課堂上使用，觀察學生的反應，再回來告訴 AI 哪裡需要修改。

這是只會寫程式的人很難擁有的優勢。

## 結論

> 用你獨特的教學洞察，去指揮 AI 這個能力很強的實習生，才有機會做出真正有價值的工具。

AI 不知道你的學生為什麼學日文，但是你知道。
